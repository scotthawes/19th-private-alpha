## The synthetic triangle

Built because the CAS corpus cannot be uploaded to a third party. It is deterministic: run
`python3 scripts/make_triangle.py` again and both CSVs are byte-identical, which
`synthetic_triangle_params.json` lets you check.

Shape is 10 origins by 10 development periods, observed in the upper triangle only — the
same shape as the real triangles, so depth and anchors mean the same thing. Generation:
exposure grows 3% per origin with lognormal noise, ultimate loss ratio 0.68, age-to-age
factors decaying from 2.60 to 1.01, and non-negative lognormal incrementals so cumulative
paid can never decrease.

The declared factors are recoverable from the output: volume-weighted over origins observed
at **both** ages, they land within ~1% of the inputs (2.53 vs 2.60, 1.67 vs 1.65, 1.31 vs
1.32, …). Pooling across *unmatched* origin sets is the wrong estimator and produces
factors below 1 — a trap for anyone re-deriving them.


## The alpha's demo files

The four demo CSVs are attachments on the Notion invite page, so they can only be
downloaded by the invited account. Save them here with these names:

- `breast_cancer_diagnostic.csv` — predict `diagnosis` (malignant / benign)
- `kepler_koi.csv` — planet vs false positive, from NASA's Kepler catalog
- `support_intents.csv` — 77 banking support categories
- `machine_failure_binary.csv` — machine failure, from torque / operating-time style readings

If you drop the official `breast_cancer_diagnostic.csv` here, it replaces the
reconstruction and everything else keeps working — regenerate with
`python3 scripts/make_demo_data.py --force` if you ever want the local copy back.

## Before you train on anything real

- **One prediction moment.** Every input column must be knowable at the point you will
  actually predict. A column filled in after the outcome happened is leakage, and it will
  make the model look far better than it is.
- **No raw free text.** The CSV workflow does not model text. `support_intents.csv` works
  because its messages are already reduced to features; if you bring your own text, produce
  the same features at prediction time.
- **Keep known labels.** For classification with labels, keep them. Use 19th's labelling
  workflow (`spec.labeling`) only when the target column is absent or entirely empty.
- **Don't commit customer data.** This repo is private, but data still does not belong in
  git history. Add real CSVs to `.gitignore` before the first commit that contains them.
